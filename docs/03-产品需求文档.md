## 2. 产品背景

### 2.1 问题陈述
Flask 开发者在构建后台管理系统时面临以下痛点：
- 需要额外搭建前端项目（React/Vue），增加开发成本
- 现有 admin 插件（如 Flask-Admin）UI 老旧，不符合现代审美
- 集成复杂，需要大量配置和自定义代码
- 缺乏开箱即用的用户管理、权限控制功能

### 2.2 解决方案
Flask Admin Pro 提供一个零构建、即插即用的后台管理系统：
- 通过 CDN 引入 Element Plus，无需 npm/webpack
- 一行代码集成到现有 Flask 项目
- 内置用户管理、权限控制、模型 CRUD
- 现代化 UI，支持主题切换和黑夜模式

## 4. 功能需求

### 4.1 功能优先级矩阵

| 功能 | 重要性 | 紧急性 | 优先级 |
|------|--------|--------|--------|
| 登录认证 | 高 | 高 | P0 |
| 用户管理 | 高 | 高 | P0 |
| 模型 CRUD | 高 | 高 | P0 |
| 仪表盘 | 中 | 高 | P0 |
| 主题切换 | 中 | 中 | P1 |
| 黑夜模式 | 中 | 中 | P1 |
| 请求监控 | 低 | 中 | P1 |
| 批量操作 | 低 | 低 | P2 |
| 数据导出 | 低 | 低 | P2 |

### 4.2 详细功能说明

#### F1: 登录认证
- **描述**: 用户通过用户名密码登录系统
- **输入**: 用户名、密码
- **处理**: 验证凭据，创建会话
- **输出**: 登录成功跳转到仪表盘，失败显示错误提示
- **验收标准**: 
  - 正确凭据可登录
  - 错误凭据显示友好错误
  - 未登录访问自动重定向到登录页

#### F2: 用户管理
- **描述**: 管理员可管理后台用户
- **功能点**:
  - 用户列表（分页、搜索）
  - 新增用户
  - 编辑用户（含密码修改）
  - 删除用户
  - 角色分配（admin/operator）
  - 启用/禁用用户
- **验收标准**: 所有 CRUD 操作正常，数据持久化

#### F3: 模型 CRUD
- **描述**: 自动扫描 Flask-SQLAlchemy 模型，生成 CRUD 界面
- **功能点**:
  - 模型列表展示
  - 自动识别字段类型
  - 列表展示（分页、排序、搜索）
  - 新增/编辑/删除记录
  - 日期时间字段特殊处理
- **验收标准**: 支持常见字段类型，操作无报错

#### F4: 仪表盘
- **描述**: 展示系统概览和统计数据
- **功能点**:
  - 用户数量统计
  - 模型数据量统计
  - 最近请求日志
  - 快捷操作入口
- **验收标准**: 数据准确，展示清晰

#### F5: 主题系统
- **描述**: 支持多种主题色和黑夜模式
- **功能点**:
  - 5 种主题色（蓝/紫/绿/橙/红）
  - 黑夜模式切换
  - localStorage 持久化
  - 跟随系统黑夜模式
- **验收标准**: 切换即时生效，刷新后保持

#### F6: 请求监控
- **描述**: 记录和分析 API 请求
- **功能点**:
  - 请求量统计（按小时/天）
  - 响应时间统计
  - 错误请求追踪
  - 请求日志列表
- **验收标准**: 数据准确，查询正常

## 6. 技术约束

### 6.1 必须使用
- Flask 2.x
- SQLAlchemy
- Vue 3 (CDN)
- Element Plus (CDN)
- Jinja2

### 6.2 禁止使用
- Node.js 构建流程
- webpack/vite 打包
- 额外的前端服务器

### 6.3 可选使用
- Peewee ORM（通过适配器）
- Redis（会话存储）
- PostgreSQL/MySQL（生产数据库）
